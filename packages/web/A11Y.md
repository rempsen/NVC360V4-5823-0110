# Accessibility gate

`a11y-gate.py` drives all 24 admin pages in real Chrome at 390px and 1440px and
fails if it finds a control a screen reader or voice control can't address.

## Running it

The gate tests the **built** app, served by the dev server — not your source
files. So rebuild first, or you'll be auditing a stale bundle and get a false
pass:

```bash
# dev server must be up (tmux 'web', port 4200)
bunx vite build          # <-- required, the gate reads dist/
bun run a11y             # exit 1 on any new finding
bun run a11y:report      # list findings, always exit 0
bun run a11y:baseline    # accept current findings as the allowlist
```

## What it checks

| Check | Fails when | Fix |
|---|---|---|
| `ctlNoName` | a button/link/`[role=button]` has no accessible name | add `aria-label` (plus `title` for a hover tooltip) |
| `inputNoLabel` | an input/select/textarea has no label | add `aria-label`, or a `<label for=...>` |
| `imgNoAlt` | an `<img>` has no `alt` attribute | `alt=""` if decorative, real text otherwise |
| `tinyTap` | a tap target is under 32px at 390px | add padding (not font-size) |
| `overflow` | the page is wider than a 390px viewport | `overflow-x-auto` on the table, or `min-w-0` on the flex child |
| `loadError` | the page threw or timed out | a real bug, not an a11y one |

An accessible name is resolved from `aria-label`, `title`, text content, a
child `img[alt]`, or `aria-labelledby` pointing at real text — so a button with
visible text needs nothing extra. Only icon-only controls are ever flagged.

## The allowlist

`ALLOWED` in the script holds findings we deliberately accept, each with a
reason. Currently: Leaflet's own marker and control DOM, which we don't own —
the map pages expose the same data in an accessible list alongside the map.

Keep that list short and shrink it over time. `a11y-baseline.json` (written by
`--update-baseline`) is the other escape hatch: it records pre-existing
findings so the gate can be adopted without a big-bang fix. It's currently
**empty**, because the admin surface is clean — keep it that way.

## Do NOT put this in `bun run build`

The platform runs the build script to deploy. This gate needs Chrome, a booted
server and a live database; wiring it into `build` would fail in that
environment and block publishing. Same reason `scripts/smoke-build.mjs` is kept
out of `build` and lives in `build:smoke`. Run the gate in CI as its own step
against a running server, or locally before a PR.

## Why it exists

An August 2026 audit found 43 icon-only controls with no accessible name and 3
unlabelled selects across the admin. All were fixed — but nothing stopped the
next icon-only button from reintroducing the problem, and a screen-reader user
hits it long before we run another manual audit.

The gate was verified by sabotage, not by assuming it works: adding an
unlabelled icon-only button to `/admin/tags` and rebuilding makes it exit 1 and
name that exact element and page. Removing the button makes it pass again. If
you change the gate, re-run that test.
